# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An unofficial Android (arm64) port of the original Xbox game *Need for Speed: Most Wanted* Black Edition (title 4541007B), built from the Android host of [Black-Android](https://github.com/RanggaCasper/Black-Android) as [ShaolinMonks-Android](https://github.com/RanggaCasper/ShaolinMonks-Android) carries it, and made with the [XboxXBE-Recomp](https://github.com/TGP482/XboxXBE-Recomp) SDK. The game's x86 code in `default.xbe` is statically recompiled to C++ on a Windows PC. That C++ is then built for Android together with the SDK's portable runtime and this repo's host code. Drawing goes through Vulkan 1.1, and windowing, input and audio through SDL3. The repo ships no game assets. `assets/`, `iso/` and `generated/` hold the user's own files or files derived from them, and all three are gitignored.

## Build

Everything runs on Windows. Requirements: Visual Studio 2022 C++ tools, plus Android SDK Platform 34, NDK `28.2.13676358` and CMake `3.31.6`. Java 17–21 is needed for Gradle 8.7 (`.vscode/settings.json` points to JDK 17). Python is used only to pull the xbe out of an ISO.

- `build.bat` runs the full pipeline:
  1. Checks the tools.
  2. Gets `assets/default.xbe`. If it is missing, `python -I tools/xdvdfs.py <iso> default.xbe assets/default.xbe` extracts it from `assets/*.iso` or `iso/*.iso`.
  3. Builds the recompiler (`tools/CMakeLists.txt` → `out/build/android-tools/xbe_recomp.exe` and `xbe_symbols.exe`) with clang-cl.
  4. Writes the `[symbols]` table into `config/game.toml` with `xbe_symbols`, only if the file doesn't have one yet.
  5. Runs `xbe_recomp config/game.toml --xdk <sdk>/xdk` → `generated/game/`.
  6. Runs `gradlew.bat assembleRelease`.
- To rebuild only the APK after editing host code (no re-recompile): `gradlew.bat assembleRelease`. Output: `app/build/outputs/apk/release/app-release.apk`, signed with the debug key.
- After editing `config/game.toml` (hooks, symbols, ABI, partitions), the recompile step has to run again. Run `build.bat`, or run the two `out/build/android-tools` commands by hand.
- `gradlew.bat assembleDebug` still builds the native code as Release: unoptimized recompiled code is too slow to run.
- Install: `adb install -r app/build/outputs/apk/release/app-release.apk`. On the device, settings (`mostwanted.toml`, `android.toml`, `layout.toml`) and the shader cache are in `Android/data/com.racas.mostwanted/files`; saves in `/storage/emulated/0/MostWanted/hdd` and logs in `/storage/emulated/0/MostWanted/logs` (`HddDir`, `LogDir` in `native/main.cpp`). All files access is required: the activity's dialog can't be turned down, and `main` waits for the MostWanted folder to be writable before anything else (`WaitForSharedAccess`). The first launch after an update from a version with the saves in `files/hdd` copies them to `MostWanted/hdd` (through `hdd.copying`, renamed when complete) and leaves the old copy; a failed copy plays on the old one. Crashes go in the same folder as `crash_<date>.txt` at the next launch (`CrashLogs.java`): Android 11+ hands the app its own exits (`ApplicationExitInfo`), a native crash's tombstone (protobuf from Android 12, written out as tombstone text), an ANR's traces.
- The first native build compiles 128 partitions of recompiled code and takes 30–90 minutes.
- `-PxbeGenerated=<dir> -PxbeImage=<file>` makes Gradle build recompiled code from somewhere other than `generated/game`.

There are no tests or linters in this repo.

Linux (x86-64): `./build.sh` runs the same pipeline natively with clang: the recompiler into `out/build/linux-tools`, `default.xbe` from an ISO with `tools/xdvdfs.py`, the symbols, the recompile, then the root `CMakeLists.txt` as an executable, `out/build/linux/mostwanted` (`-march=x86-64-v2`; `./build.sh debug` sets `XBE_VERBOSE_LOG`). To rebuild after host edits: `cmake --build out/build/linux --target main`. SDL3 is the system's (`find_package(SDL3)`), else fetched and linked statically. The game is looked for in `assets/` or `iso/` beside the executable or in any folder above it, then the working folder (`native/game_files.cpp`); a loose `default.xbe` counts as the extracted game only with its `NFS` folder beside it, else the `.iso` beside it is mounted (the build leaves the extracted xbe in `assets/`, and taking it alone booted with no data and crashed in 0x1C0BD0); settings, `hdd`, `logs` and `shadercache` go beside the executable.

Performance: an empty file named `perf` in `Android/data/com.racas.mostwanted/files` turns on `XBE_PERF` (`native/main.cpp`). The log then gets a line a second from `D3DDevice_Swap` (`src/d3d/d3d8.cpp`, counters in `src/d3d/gpu_frame.h`): fps, the title thread's own time, the render thread's, GPU time from timestamps, draws and renderings; and every 600 frames the frame's renderings with the GPU time of each. `-Pdebuggable` makes `simpleperf record --app com.racas.mostwanted` work; symbolize with the unstripped `libmain.so` under `app/build/intermediates/cxx`.

## CI/CD

`.github/workflows/build.yml` runs on Windows for each `v*` tag, and by hand (workflow_dispatch, artifact only). It decrypts `ci/default.xbe.enc` (not in the repo yet: make it with the command in the workflow's header) with the `XBE_KEY` secret (AES-256-CBC, PBKDF2, 200000 iterations; the command to make it is in the workflow's header), checks its SHA-1, runs `build.bat` with `GRADLE_ARGS` setting `-PversionCode`/`-PversionName` from the tag, and for a tag publishes a release with `ci/release-notes.md` and the commits since the previous tag. `app/build.gradle` signs with a release key from the `BLACK_KEYSTORE*` environment variables when they are set (the workflow sets them from the `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` and `KEY_PASSWORD` repository secrets), else the debug key. Releases since v1.0.0 are signed with the keystore in `.local/` (gitignored); a different key breaks every installed copy's updates. `UpdateChecker.REPO` names the repository whose latest release the app checks.

## Where the SDK comes from

The SDK is vendored in `sdk/` (upstream commit in `sdk/UPSTREAM_COMMIT`), changed in three places: `kPhysicalSize` is 128 MB (see Memory below), `ExQueryNonVolatileSetting` takes XC_LANGUAGE from a weak `app::ConsoleLanguage()`, which `src/game/game.cpp` defines, and `kernel/files.cpp` reads D:'s files from `SetDiscOverlay`'s folder (`MostWanted/mods`) when they are there. Keep `kernel/objects.cpp` notifying every waiter on every signal: notifying only the waiters of the object that changed hung Most Wanted in loading screens (the title spun at 0x087AB5 walking a stream list another thread never filled). Both `CMakeLists.txt` files look for the SDK in this order: `sdk/` in the repo, then `../XboxXBE-Recomp` beside the repo. If neither exists, they FetchContent the SDK's `main` branch. A sibling checkout lets you read or change the runtime (`<sdk>/runtime/{app,core,kernel,xdk,gpu,audio}`), whose headers (`app/app.h`, `kernel/kernel.h`, `xdk/hle.h`, `core/input.h`, ...) the host code includes. Gradle's `fetchSDL` task shallow-clones SDL `release-3.4.16` into `third_party/SDL`. Its Java sources go into the APK and its C side becomes `libSDL3.so`. glslang, toml++ and imgui are fetched by CMake.

## Architecture

The root `CMakeLists.txt` builds one shared library, `libmain.so`, which SDL's activity loads. It is made from:

- **`generated/game/`**: recompiler output (`x86_recomp.N.cpp` for N < `partitions`, `x86_func_mapping.cpp`, `image_symbols.h`). Compiled with `-O2 -w`. Never edit it by hand. Change `config/game.toml` or the host code and recompile instead.
- **The SDK runtime** (`<sdk>/runtime/*/*.cpp`), without the Windows-only parts and the parts this repo replaces. The regex filter in `CMakeLists.txt` drops `app/`, `core/input.cpp`, `gpu/d3d12`, `gpu/render_thread`, `audio/xaudio2`, `xdk/dsound` and `xdk/d3d8`.
- **`src/`**, the game-specific host, organized as `src/<area>/*.cpp` and globbed by CMake:
  - `src/game/`: game hooks and patches. `game.cpp` has the language glue (`app::ConsoleLanguage`) and `WidenAspect` (the cameras' frame width at 0x427C00 set to the frame's aspect). `fe_mouse.cpp` makes the touch screen FEng's mouse (below; its interface is `src/common/fe_mouse.h`). `options_menu.cpp` puts the settings in the game's own OPTIONS menu (below). No `[[hook]]` yet. The code carried over from Black (weapon cheats, mouse look, walk key, FOV, typed names) and Shaolin Monks (cheats, menu and prompt taps found in what it drew) is gone.
  - `src/d3d/`: the title's Direct3D 8 (XDK 5849) entry points. `Direct3D_CreateDevice` also sets the device fields the library's init would (FVF shader, vertical blank event, display flags) and starts the vertical blank thread, which Black did from a hook. `render_thread.cpp` records D3D calls on the game's render thread and replays them on a dedicated Vulkan thread. Vertex, texture and surface memory is read at draw time, the way the console GPU reads it, so XDK fences, busy checks and locks wait on that replay.
  - `src/sound/`: DirectSound reimplemented (buffers, streams, ADPCM decode, mixer, reverb).
  - `src/common/`: `game_info.cpp` defines `app::kGame`, the struct that describes the game to the runtime (title, settings file, option bindings, load/save/init, pad and rumble filters, UI callback). Also here: the settings' rows (`menu.cpp`: `app::rows`, which the game's options menu shows, and the CHEATS page, which the game's menu does not show; the ImGui panel, on F10 and the touch gear, shows the CHEATS page alone, the gear pausing a race first (Start) and opening the panel once the press is out), `options.h` (`game::Options`, saved to `mostwanted.toml`) and translations.
- **`native/`**, the Android host, shared with Linux. On Linux `main_linux.cpp` replaces `main.cpp` (the window and its display modes, F11/Alt+Enter, the settings beside the executable, a crash handler that logs the guest stack); the other files build for both, Android-only code (JNI, the activity, Android's window pointer, the battery) under `#ifdef __ANDROID__`, and `src/d3d/render_thread.cpp` has SSE2 beside its NEON. On Linux the touch screen's prompts ("Tap anywhere") are off (`src/game/prompts.cpp`), the touch controls show only after a touch, ANDROID OPTIONS is LINUX OPTIONS, and the update check opens the releases page. `main.cpp` runs SDL's window and event loop, the app lifecycle and foreground/surface handling. `vulkan.cpp` is the Vulkan backend, and `vk_shader.cpp` compiles the SDK's HLSL shader translations to SPIR-V with glslang. The rest: `touch.cpp` (touch controls and layout editor, plus keyboard and mouse), `gyro.cpp` (tilt steering), `input.cpp` (controllers, and the settings panel's CONTROLLER page bindings, saved as `[pad]` in `mostwanted.toml`, laid over SDL's mapping), `audio.cpp`, `ui.cpp` (ImGui), and `game_files.cpp`, which finds the game files or ISO and checks the xbe's SHA1 against `kImageSha1`. `host.h` declares the interfaces these parts share. `native/compat/crt.h` is force-included into all host sources (not the generated ones).
- **`app/`**: Gradle module. `MostWantedActivity.java` (package `com.racas.mostwanted`) extends `SDLActivity`. It asks for all-files access (the storage permission on Android 10) and creates `/storage/emulated/0/MostWanted` and `files/assets`, which are where the game files are looked for, along with a `MostWanted` folder at the top of each SD card. `UpdateChecker.java` asks `REPO` (RanggaCasper/MostWanted-Android) for its latest release; it is off while `REPO` is empty.

### How recompiled code reaches the host

`config/game.toml` is the recompiler's input:
- `[xbe]`: path, entry point, XDK version, output dir, `partitions` (CMake reads this number to list the generated sources), and code sections.
- `[symbols]` / `[data]`: addresses of library functions and globals in the image, 0 where the image has none. Host code refers to them through `SYM(Name)` from `image_symbols.h`.
- `[abi]`: register-argument conventions for link-time-code-generated XDK functions.
- `[[hook]]`: entries `at = <x86 address>`, `call = "<Name>"`. The recompiler emits a call at that address to a host function `void Name(X86Context& ctx, uint8_t* base)`, defined in `src/game/`. To add a hook, add the `[[hook]]` entry, define the function, and recompile.

Host code reads and writes guest memory through the kernel helpers (`HostPtr(va)`, `R32`, ...) and guest registers through `X86Context`.

### Supported game versions

Only the USA Black Edition disc: `default.xbe` SHA-1 `f636a16af04171089f879a4bed646e185c734233` (4,739,072 bytes, XDK 5849). The disc root holds `default.xbe`, `update.xbe`, `dashupdate.xbe` and `NFS/` (the game data: `ZDIR.BIN` and `ZZDATA*.BIN`).

### Notes on this image

- No `[abi]` entries: the D3D library is not link-time code generated.
- `xbe_symbols` finds 165 of 238 functions and all 12 data symbols. The other functions are not linked: the `.XTLID` table lists every library export the title uses, and the missing ones are not in it. Resolved by hand at the top of `[symbols]`, each with the code that proves it: `D3DDevice_Reset`, `SetPalette`, `BeginPush`/`EndPush`, `LoadVertexShaderProgram`, `IsBusy`, the three visibility test calls, and `IDirectSoundBuffer_Pause`/`SetEG` (`.XTLID` B0057 and B0067: the DSOUND exports are numbered in alphabetical order). `D3D_FvfShader` (0x384468) is loaded by `D3DDevice_SetVertexShader` at 0x373927.
- The stream exports `.XTLID` B0080, B0090, B0095 and B0096 are thunks to `CDirectSoundStream_FlushEx`, `SetHeadroom`, `SetMixBins` and `SetMixBinVolumes`, which are replaced; B00A3 is `XAudioCalculatePitch`, arithmetic left recompiled.
- Frame shape: 0x427C00 (853, 480 x 16/9 with the widescreen flag) is the front end's and HUD's screen transform (0x0D4888, 0x0D8330: 576 / width across, 448 / 480 down, times the profile's scale at 0x427BFC), set to 480 x the frame's aspect (`game::WidenAspect`). The 576 and 448 (0x3D3534, 0x3D3530, read only by those two transforms) are the console's title safe area: the front end, its movies and loading screens had a black border about the frame, so `game::FullFrameFrontEnd` makes them 640 and 480 (the HUD reaches the edges too); `fe_mouse.cpp`'s keyboard hit test reads them back. The 3D views' projection (0x0C7740, thiscall, ecx the view's matrices) takes the camera's 16 bit horizontal angle ([[eView + 0x40] + 0xC4]) for the x scale (+0x40) and that angle times 9/16 (3/4 without the flag) for the y scale (+0x54): wider than 16:9 the picture was stretched. `src/game/game.cpp` multiplies the x scale by (16/9) / aspect (Hor+) for the views drawn over the frame (types 1, 2, 4 to 7) inside the call, just before the view x projection product (0x2B91C4 at 0x0C7A04) the frustum's planes come from.
- Vertex programs: besides `SetVertexShader` the game loads programs into the NV2A's 136 program slots (`LoadVertexShaderProgram`, 4 callers) and runs them with `SelectVertexShaderDirect` (0x372F20, 9 callers), which copies a `D3DVERTEXATTRIBUTEFORMAT` to its static record (0x384350, the format at +0x14) and jumps to `SelectVertexShader`. `src/d3d/d3d8.cpp` keeps the slots and makes one `gpu::VertexShader` per inputs and program it is asked to select.
- The Vulkan backend counts no visibility test pixels; `GetVisibilityTestResult` gives 0, which the sun's glare (0x0D5AB0) reads without checking the result.
- 0x2CDBAA is SSE2 code (the recompiler leaves its `pxor`, `psraw`, ... unimplemented); nothing calls or points at it.
- Frame buffers: the present parameters give the title's own surfaces (`BufferSurfaces` 0x0047E1F4/0x0047E478, `DepthStencilSurface` 0x0047FFE8, a 1280x480 multisample depth). Like the library (0x3789D0), `src/d3d/d3d8.cpp` keeps copies of the buffer headers, sized as the present parameters say, and Swap turns the copies over; the title trades its own headers' memory itself before each Swap (0x0C8DA3) for the textures its visual treatment reads. Turning the title's headers too made every other frame black.
- Graphics switches in the QUALITY page, `src/game/game.cpp`: CAR REFLECTIONS (`car_reflections`: FULL, HALF, QUARTER, OFF): the cars' environment cube is drawn as views 0x12 on (0x0D7AD5, face 0's target at [0x48B4C0], the faces' views 0x70 apart) only while the byte at 0x4279D6 is set, one of a row of render switches at 0x4279CC (all 1) the game reads and never writes; HALF and QUARTER set it every 2nd or 4th frame, but every frame out of a race and in a race's first 120 frames (`game::Racing`): a race's cube is new, and its cars stayed white until the count came round. OFF: `native/vulkan.cpp` binds an opaque dark grey cube (matched by address too, `game::g_env_cube`), and the game still draws it every 512th frame: off from the start, a cube never drawn left the paint white whatever was bound. The faces cost about 3% of the GPU's frame. ROAD REFLECTIONS (`road_reflections`): the dword at 0x427A3C, read only at 0x0D787B, gates the wet road's reflection (views 4 and 5); the road still samples view 4's target, so off binds opaque black for it (`game::g_road_reflection`). SHADOWS (`shadows`): the dword at 0x469910, read only by a car's render (0x255490), gates the shadow under each car (0x24C0F0 with the CARSHADOW texture at CarRenderInfo +0xE0, 0x24BB90 with the one at +0xE4). The trees' and buildings' shadows on the road are the frame's one 2x multiply draw into the frame (blend DST_COLOR/SRC_COLOR); SHADOWS off skips it in `native/vulkan.cpp`. (A pale car once blamed on that skip was CAR REFLECTIONS off.) PARTICLE EFFECTS (`particles`): the byte at 0x4279CF, read only at 0x0D81FC, gates the particle system's draw (0x0CE8B0, the system at 0x482CC0). Not the master switch at 0x434130, which also stops spawning (0x0DA296 to 0x0DBEE4): loading a race with it at 0 corrupted the game's heap, a crash in the allocator 0x054DC0 under 0x1C0D50. The game's switches are written by `game::ApplyGraphicsSwitches` at each present. SCREEN RAINDROPS (`rain_drops`): 0x0CC530, the "Rain Drop" pass (20 drops, 40 renderings a frame), returns at once. FALLING RAIN (`rain`): 0x2527A0 draws a view's precipitation ([view + 0x68], views at 0x48ACF0, 0x70 each; 350 drops at +0x33D8, the RAINDROP texture at +0x3404) and returns at once; its caller 0x25E770 still works out the rain's strength (+0x290) that wets the road. YELLOW TINT (`yellow_tint`, off by default): the "Visual Look Pass" (0x0CDA40, pixel shader 0x17 of the effect table at 0x42A858) is lerp(luma, scene, +0x98), the scene times a curve of its alpha by +0x90, plus the scene times a tint ramp (texture 3, 256x1 at [this + 0x234]), plus the 320x240 copy by +0x170, times 1 + 4 x +0x174. 0x0C1BD0 builds the ramp from the curve at +0x50 and the RGB at +0xA0/+0xA4/+0xA8, the yellow; off, that colour is its luma while the ramp is built and is given back after. The pass is not skipped: it reads the scene (0x47FC2C) and draws to [this + 0x298], likely the frame itself. NIGHT MODE (`night_mode`, off by default): nocturnal mod turning daytime into night: 0x0C1BD0 builds the tint ramp with cool moonlight blue (0.15 R, 0.32 G, 0.68 B luma), 0x0CDA40 clamps overbright bloom to 0.20, sun glare (0x0D5AB0) and sun disk/rays (0x0D5CA0) are skipped, sky dome multipliers at 0x42FDA0 and 0x42FDB0 are set to midnight blue ({0.10, 0.15, 0.32, 1.0}), which the frame's sky loop (0x0D7708, layers 0 to 2 of one model, 0x4D5E28, its textures renamed per layer by 0x244B00) multiplies each layer's colour (0x42FE00) by; the layer draw's other callers (0x244B70 from 0x0D6D0B, 0x0D7BF3, 0x0D7E24) have it multiplied in the hook, horizon haze at 0x4279D7 is cleared, distance fog color in `native/vulkan.cpp` is darkened, headlights and flares on all cars are illuminated by setting bits | 7 in 0x24AB90 (`PVehicle::mGlareState`), and car headlight beam ground projection on the road surface is enabled via 0x24ABE0 with illuminated beam color at 0x469B0C (soft warm translucent beam `0x48FFF4D8`) and geometric quad tuning at 0x469ACC..0x469B00 (12m conical beam matching headlights to prevent road contour clipping/floating). MOTION BLUR (`motion_blur`): the "Motion Blur" pass 0x0D1440 (cdecl, 4 args, from the "Visual Look Filters" 0x0D21D0 while the byte at 0x42F51D is set) returns whether it drew, and the "Radial Blur Mask Pass" (0x0CE1C0, nitrous and speedbreaker) runs only then; slow, it returns false having drawn nothing (0x0D1661), so off returns false at once.
- Cheats in the ImGui panel (its only page), not the game's options menu (`src/game/game.cpp` `ApplyCheats`, at each present): INFINITE NITROUS and INFINITE SPEEDBREAKER set debug bytes the game reads and never writes, 0x49A61C (the NOS drain at 0x1E6A9A is 0, every car's) and 0x4B9694 (LocalPlayer's speedbreaker drain at 0x20E663). MAX CASH keeps CareerSettings::CurrentCash, `[[0x48EDD4] + 0x10] + 0xB4` (the FEDatabase's first profile), at 9,999,999; it ends up in the save. NO POLICE sets the cop manager's byte at +0x60 (`[0x494E40]`, ICopMgr vtable 0x3CB4D0), which the scripts' NoNewPursuitsOrCops sets (0x0130E0) and VehicleSpawningEnabled (0x01A370) reads: no new cops or pursuits; a pursuit already on goes on. Off gives the byte back. UNLOCK ALL holds UnlockAllThings, the byte at 0x493D00 (SkipFE 0x493C40 + 0xC0, as on the PC), which every unlock test ors in; the game sets it itself in one menu (0x1049FA), so off gives it back too. NO TRAFFIC: the traffic density 0x22CC0 (AITrafficManager's update 0x35A50, its only caller) gives 0, and the manager's cars about are told to leave; a drag race's traffic is a script activity's instead (0x181120, a car at a time through the race), which with the cheat on makes no car but a cop. AUTO SHIFT IN DRAG (`DragShiftFrame`, at the present): the player's ITransmission (0x11FB0), when it is EngineDragster's, shifts up with its own Shift (vtable +0xC) at 97% of the redline; EngineDragster never works out the shift potential the drag HUD shows. NFSPluginSDK (berkayylmao) has the PC's class layouts, the same as the Xbox's.
- SKIP MOVIES (`skip_movies`, `src/game/game.cpp`): the movie screens' NotificationMessage (FEAnyMovie 0x116230, InGameAnyMovie 0x131A30, the boot's EA logo/PSA/intro/attract 0x1311B0, whose byte +0x2C allows the skip) stop on A/START (0x406415E3/0xB5AF2461) and post the movie's end (0xC3960EB9); the 10th per-frame tick (0xC98356BA) of each screen is taken for A, once a screen (forgotten in its destructor); the boot's screen only once its byte allows (forcing it hung the attract movie), and a player's press after the skip is taken for a tick, as a second end hung the attract movie on its frame. The engine's own cutscenes (NIS: rival intros, the career's opening) are not movies and still play: NISActivity is the class at vtable 0x3E60C0 (GetName 0x21A7F0), the counter at 0x4C8800 is above 0 while one plays (0x214399/0x215E10), and HUDACTION_SKIPNIS (0x32) maps to category 2, bit 0x80000 in 0x21DD60; what reads that bit is not found yet.
- The ImGui panel draws with the game's body font (`src/game/game_font.cpp`, `ui::ApplyGameFont` in `native/ui.cpp`): once FONT_MW_BODY is loaded (cFEng's font list at 0x48F2F0, the node's name hash at +0x14 = bStringHash("FONT_MW_BODY") 0x545570C6, its TextureInfo at +8, its FNTX resource at +0xC), its glyphs (16 bytes each: Unicode +0, width +2, height +3, texture x/y +4/+6, x offset +9, y offset from the line's top +0xA, advance +0xE) are cut out of its 256x256 linear DXT3 texture and laid into ImGui's atlas as custom glyphs over ProggyClean at the game's line height (+0x24, 23), which stays for what the game's font lacks; the renderer uploads the atlas again (`ImGui_ImplVulkan_CreateFontsTexture`, which waits for the queue). Until then (the first seconds of the boot) the panel is ProggyClean. `FontGlobalScale` brings the taller font to the 13 px the panel was laid out for.
- The retail build's PIX marker stub 0x377A70 (`xor eax, eax; ret`) is called with each pass's name ("World Render", "Car Render", "Rain Drop", "EnvMap %d", ...) and each loose model group's (0x0D62A0): wrapping it to log names maps the renderer. It is shared by other empty functions, so check the name pointer with `mem::IsCommitted` before reading it.
- EA's file streams ("STRM" at 0x87xxx, the movies' reader): the stream thread fills a handle (0x871D0) under the system's critical section, the bytes ready (+8) before the first block (+0xC); the reader 0x87A40 read both before entering it, and on the phone's cores it took a block not set yet (0xEEEEEEEE, bMalloc's fill at 0x539CE), a SIGSEGV as a movie started (0x102B10) or stopped (0xEB580). `src/game/game.cpp` holds the section around the whole read. Other code reading another thread's data with no lock may need the same: x86 kept stores in order and the console had one core.
- Threads (`src/game/threads.cpp`): the main thread and the file system's three job threads (guest 1C, 28, 34, EA's queue 0x2BD01F, jobs' Execute at vtable +4) run at once. A file's read is two calls on its handle, seek (SetFilePointer, raw device vtable 0x3EE468 +0x1C, 0x2BE8A3) then read (ReadFile with no OVERLAPPED, +0x14, 0x2BE83E), and the ZDIR files (vtable 0x3E05C8: open 0x1C0D50, close 0x1C0E00, read 0x1BA800) seek and read their ZZDATA archive's one shared handle: another thread's seek between the two and the loader got another file's bytes, which crashed walking chunks (0x1C0460, its assert 0x1C0130, 0x1B9620), in 0x238A70 (a scenery pack's table +0x30 null), and as heap damage the heap check found (0x54180 with 1, int3 at 0x54281, from 0x240690). 0x1BA800 and the jobs' read/write (0x2BE225, 0x2BE32C, 0x2BE433) hold one lock. EA's slot pools (free list +0x10, count +0x18; alloc 0x54DC0, 0x54E20, free 0x53570, 0x55220, teardown 0x54EF0) have no lock, and the file handles' (0x49362C) is taken by 0x1C0D50 on any thread: a slot handed out twice had its path over the list's next pointer (0x54DC0 reading "soun", "TRAC"); they hold another. bMalloc's heaps have a section each (+0x3C, 0x2BC401/0x2BC40C), the string pool too (0x476C58 +0xC). The music's level (0x2D6D40) is the game's but for a playing channel with no stream yet (+0x12C 0, after a boss race), whose call it skips.
- My Music (`native/music.cpp`, `src/common/music.h`, the panel's MY MUSIC tab in `src/common/menu.cpp`, `game::MusicFrame`): every sound file in `MostWanted/music` (`Artist - Title.mp3`, a subfolder the album) is on a list of its own, with no limit, its order, modes (bits, as EA Trax's: 1 menus, 2 racing), sequential or random and what plays (My Music or EA Trax) kept in `playlist.txt` there. Decoded by NDK media and added in `audio.cpp`'s `Feed` after the game's mix. The game's EA Trax list is left alone. The game's music shares one buffer with its other sounds, so EA Trax is stopped in the game, by the profile's switch +0x78 (`[[0x48EDD4] + 0x10]`; +0x74 is Interactive Music, which goes on in pursuits), given back when EA Trax is chosen again; it begins at the main menu (a package named MainMenu*) or a race, whichever comes first; the level is the sliders', menu music +0x54, game music +0x58, and a song's beginning shows on EA Trax's banner (0x1443C0, title, artist, album). A folder that reads empty is read again every 5 seconds. For anyone going further: the list's rows read the records of `[0x47A7BC]` by song id (+0 artist, +4 title, +8 album, +0x10 the stream's event; `[0x430F74]` the count, 26), from a vault class in ATTRIBUTES; its list is profile +0x324 (8 byte rows: id, mode byte), +0x7C 0 sequential, 1 random; the player's start is 0xB9B80 (an event to play, or 0 for the next), its update 0xB9DA0, the stream's level 0x2D6D40, called only by EA Trax. The picker's mask is 28 bits and the save's list has no room for more, which is why My Music is a list of its own.
- Saves (`native/saves.cpp`, `src/game/saves.cpp`): a profile file (E:/UDATA/4541007b/<folder>/<name>) is "MC02", its size, the header's 0x38 bytes signed at 0x38 and the rest from 0x54 signed at 0x24, both HMAC-SHA1 keyed by XboxSignatureKey, which the kernel leaves zero (XCalculateSignature reads the kernel's key straight; 0x30EC70 to 0x30ED1E); the profile is the file from 0x54 (UserProfile load 0x147600: an MD5 of its own, 0x132970). Before the boot `saves::Guard` checks each the same way, copies a good one to `MostWanted/backups/saves/<folder>/<name>/<stamp>` when it changed (ten kept) and puts a bad one (a write cut short) back from its newest good copy. The "damaged" profile of the Mods Loader's first days was not damaged: FEDatabase+8 is the hash of a fresh profile's car list taken at boot (0x157180, 0x4E6A0 over +0x414), every save keeps it (+0x5A09 of the profile, before its name) and a different one fails the load (0x14768B); add-on cars are in that list, so every change of them turned all saves away (the disc's alone 0xAE7B6735). `sub_00147600` takes the save's hash as the game's before the original compares them; car_mods.cpp puts the profile's cars right after, and moves the career's car (CareerSettings::CurrentCar, profile +0xA8, a record's handle) to another of the career's cars when its add-on went.
- Sound: EA's software mixer plays through one 6 channel PCM buffer (0x2DF96E, mix bins 0 to 5), so `src/sound/mixer.cpp` mixes up to 6 channels a voice; dropping the centre and back channels silenced cutscene dialogue and the engines.
- On Adreno `native/vulkan.cpp` uses render passes (cached, clears as load ops) instead of dynamic rendering: `vkCmdBeginRendering` allocated on every call, a sixth of the render thread in the rain, where the screen drops ping-pong 20 times a frame between the frame and a 32x32 target. Command pools are reset on a thread of their own (the driver's reset frees and remaps the buffers' GPU memory).
- SHADER PRELOADING (`shader_preload`, PERFORMANCE page, off by default): `native/vulkan.cpp` lists every shader (its key, vkey or pkey ^ kPixelKeySalt, to its HLSL's hash) and pipeline (its PsoKey, values only) the first time it is made, in `shadercache/preload.bin`, whether the option is on or not. On, a detached thread makes them all from the cached SPIR-V (`vkshader::Cached`) and `BuildPipeline`, the render passes made first on the render thread; `EnsurePipeline` and the shaders take them under `pre_lock_`, and a pipeline the render thread makes first is claimed so the thread skips it. A race and the menus are about 50 shaders and 50 pipelines; with the driver's pipeline cache they preload in well under a second.
- `native/vulkan.cpp` keeps a depth buffer larger than the target (the zeta has its own pitch); it used to drop it, and the scene drew with no depth test (the car's interior over its body).
- Split screen (two pads plugged in): each player's world is drawn into the frame with a half viewport, then each half's visual treatment is drawn to a 640x240 surface over the frame's own rows (the top one at the frame's address, the bottom one 240 rows in) and reads that half as a 640x240 texture. Targets are keyed by address, so the top half made the frame again every frame (black under the HUD) and the bottom one was a target of its own. `native/vulkan.cpp` draws and clears such a surface into the presented frame, rows down (`FrameRegion`), and a texture over a presented frame's rows is copied out of it at each bind (`BindFrameRegion`).
- Pixel combiners are read from the combiner registers (`MakePixelKey`, `sdk/runtime/gpu/shaders.cpp`), which the render thread now copies (`src/d3d/render_thread.cpp`): Most Wanted sets them with pixel shader render states after `SetPixelShader`, over a definition that is all but empty.
- The scratch push buffer walker applies the inline `SetVertexShaderConstant` (NV097 0x1EA4/0x0B80) and raw program loads (0x1E9C/0x0B00), and every draw walks it first (`SyncDeferred`).
- Fog with table mode NONE is vertex fog: a program's `oFog` is the factor (`fogp.w == 4`); Most Wanted's final combiner blends by the fog alpha.
- `D3DDevice_IsBusy` reports idle (the title spins on it at 0x0BEB30).

Geometry: PC meshes (0x134900, one vertex buffer of pos, normal, colour, uv) to the Xbox's (0x134B00, a buffer per shading group of pos, uv, normal, 96 byte groups); chunks are read at their header + 0x17 rounded down to 16, vertices + 0x87 rounded down to 0x80 (0x0C7490), solids on 0x80. LODs move up one, the Xbox's best being B. Memory: the guest has 128 MB, a devkit's, not a retail box's 64 (`kPhysicalSize`, `kernel/memory.h`, which the generated code does not include). The main pool is a fixed 55 MB (0x421BB8, read by 0x54340), 4279 KB of it free at boot; the car pool (`CarLoader`, 0x4D7B38, its size set by 0x262300, its room found by 0x260120) comes out of it, 7550 KB in a race and 6300 KB otherwise (0x433A00, 0x433A04, 0x1C7620), for all the cars in it, about 2700 KB left for the player's once four rivals are in, and a car loads about its whole file. On those sizes a 13.4 MB Audi drew nothing but its shadow in a race, a 3.8 MB one stopped the game unloading cars in use (the break at 0x2600F7), and 4 MB or 2 MB more for the car pool stopped the boot or the race's start (the main pool's break, 0x545B2). So `src/game/car_mods.cpp` adds 48 MB to the main pool and 32 MB to the car pool before the first allocation. A PC mod may repeat its best model at every LOD: `reduceLods` thins by quadric edge collapse (`Decimator`), each shading group alone, a vertex going into a neighbour so what is left keeps its uv and normal, a group's open edges last and only along themselves (grid clustering alone tore a low mesh's wheels and faceted its body; it only brings a part more than twice over near first, and finishes one collapse leaves over, a dense mesh's many open edges locking it): the lower LODs to 12, 4 and 1.5% of the part's best; a best LOD is thinned by collapse alone, never clustered (a Grande Panda's body, 160k vertices of attachments, came out in shards); a car over 12 MB has its biggest best models cut to a common triangle count, the small parts that show most (a wheel) left whole; a car kept from before is put right at the next install or removal (`fitGeometry`). A mod with no script has the Gallardo's `ecar`, and so its `TireOffsets` (x, y, z, radius; [0], [1] front) and `TireSkidWidth`: `measureWheels` takes x from the arches in the lower edge of the skin and y from the skin's width there, less what of the tire model is past its 0 (a disc car's runs inward from 0, a mod's may be centred); on the disc's cars and a scripted mod x comes within 2.5 cm, y within 1.5 cm. A car that replaces one of the game's keeps that car's. Attachment slots (a kit's ATTACHMENT0 to 9, which no disc car uses and the parts copied from BMWM3 have no row for) never draw, and some mods keep their panels there (the Tartarus's rear and canopy, all of a Veloster's body): `mergeAttachments` puts a kit's into its BODY, LOD by LOD, tables and bounds joined, and leaves a style's out; the LODs are thinned before (each attachment alone), and a body and attachment over a solid's 16 bit vertex count are thinned together till they fit (`fitMerge`): left out, an attachment never drew. Textures: the first level only, shrunk to `--max-textures`, in the Xbox's 172 byte record. JDLZ: the game's decoder (0x1BAD20) counts its input down and stops only at exactly 0, flags fetched right after the token that ran them out; a stream off by a byte writes on over the heap, which showed as crashes elsewhere with vtables of 0xF5F5F5F5 and the like. The vault (VPAK: bin, then NpeD, NrtS, NtaD, NpxE, NrtP): export offsets count from the vlt part; fixups are a group for the bin, then for the vlt; a collection is key, class, parent, reserve, shift, entries, types, layout pointer, its types, 12 byte entries; a class's fields are 16 bytes (key, type, offset, size, count, flags, log2 align; flags 1 array, 2 in the layout); an array has count, room and element size before its elements, which keep their alignment. `Attrib::StringKey` is lookup8 from 0xABCDEF0011223344, lookup2 from 0xABCDEF00 and a text the game reads: MODEL's names the car. VltEd's script is applied but for new fields, resizes and the emitter classes. FE_ATTRIB.BIN holds the frontend class's nodes (their definition is in ATTRIBUTES), +0x18 the name in `CARNAME_%s_%s`, the byte +0x40 the make in it and the car's logo (0x134250's table, 1 BMW to 25 CORVETTE, the Gallardo's 15): a copied node kept it, so an Audi looked for CARNAME_LAMBORGHINI_ and My Cars' title showed the .fng's "FENG: Default string error."; a make the game has not keeps the node's, and the name's hash goes by it. A profile keeps its stock car list (FEPlayerCarDB, profile +0x414): `ModCarsFrame` adds the car to a list older than it. The car select's name is the texture `SECONDARY_LOGO_%s`, which GetTextureInfo answers from `car_name.dxt`; a texture no pack has draws as "temp350". `.BIN`s of VINYLS and PREVINYL are ZDIR records pointing at the Gallardo's. A car named as one of the game's only overlays that car's geometry and textures. The app does all this on the phone: `ModsActivity`, "Most Wanted Mods Loader" (a launcher icon of its own, process `:mods`), only installs and removes (one at a time, selected ones, or all; cars removed together make the game's files again once): its buttons open nfsaddons.com's Most Wanted cars and nfsmods.xyz in the player's own browser, and the downloaded archive comes in through the file picker or by being opened or shared with the app (VIEW/SEND of zip, 7z, rar); nothing here fetches anything. An archive may be a pack of many cars, each under its own folder (`Binary/_setup/Car/<car>`, its script `<car>.nfsms`, `collections/CarTypeInfo_<car>.bin`): each goes in by itself and one that fails leaves the others, the game's files made once at the end, its files spooled to numbered files in the cache (`ModArchive`), as one car's model can be 90 MB unpacked. Some tools fill the gap before a mesh chunk's data with 0, not 0x11 (`modPayload`); read as data it shifted the groups, indices and vertices, and a car came out as NaNs and garbage in a structure that looked whole. A group's index and vertex counts and a solid's vertex count are 16 bits: `convertSolid` splits a denser group, `reduceLods` brings a solid under 60000 vertices. `ModArchive` reads the car's files into memory (.zip and .7z in Java, RAR of any version and a .7z the Java reader refuses by libarchive; nothing in an archive gets a path or is run), `CarConverter` is `tools/car_mod.py` in Java (a change to one goes in the other; on the Sesto Elemento their outputs differ by one pixel's palette index, Python 3.12's compensated `sum` breaking a tie) and runs on a PC too, and `ModInstaller` keeps each car in `mods/garage/<car>`, makes the game's files again from all of them at each install or removal, stops the game (its process has the old list in memory) and moves the files in, ZDIR.BIN last. A shading group's flag 0x100 (Xbox group +0x28) gives it the environment's reflection: the PC takes that from the shader and mods' tools leave it off (every mod's paint 0x14080, the disc's 0x14180), so it is set by the group's shader as every disc car's solids have it (`REFLECTIVE`/`MATTE` in both converters); cars kept from before are set in place (`relight` in `fitGeometry`), the Mods Loader offering it once while `garage/.built` is below `ModInstaller.BUILD`. Some repacks keep the car's folder loose beside their Binary `.end` scripts, no CARS above it (`EVO8 U2/LANCEREVO8/GEOMETRY.BIN`): with no CARS folder in the archive, any folder with a GEOMETRY.BIN and a TEXTURES.BIN is a car; the `CARNAME_<make>_<car>` string in any `.end` (English.end first) names it, and with no CarTypeInfo gives its make too. Older mods keep their cars in `CARS_REPLACE/<car>` (a game's car's name, so a replacement) and pack blocks as RAWW (a 16 byte header as JDLZ's, then the data as it is). A mod with no SECONDARY_LOGO gets one drawn from its name, the site's page title if it brought no strings. The stock list has 32 cars in the car select. A mod made from another car keeps that car's name inside its models (SUPRA_KIT00_BODY_A in BRIANSUPRA) with the hash of its own at +0x10, which is what the game looks up: `convertSolid` takes the name from the hash. A test with a mod's folder merely renamed, hashes and all kept, proves little: the car shows nothing and the car select waits on it for good. `cars_removed.txt` lists add-ons taken out, whose keys name nothing now: `ModCarsFrame` frees their records and their customization and career slots in the profile.
- Texture packs (`src/common/texture_packs.h`): the PC's NextGenGraphics packs (`TexturePackInfo.json`, `gameId` a texture's name or `0x` and its hash, `texturePath` under `rootDirectory`) are installed by the Mods Loader (`TexturePacks.java`) into `mods/textures/<pack>/<hash>.dds` (bStringHash of the upper-case name, `info.txt` last, its 4th line the size kept), each image at most 512, 1024, 2048 or 4096 texels across, as the player picks before it goes in (`ModArchive.isTexturePack` lists the archive's names first), with all its mips: one with mips is cut to its mip of that size, one without (or still bigger) decoded, box-shrunk a row at a time, mipped and encoded again (a bounding box DXT encoder), its first level kept when not shrunk. The archive's .dds are shrunk as `ModArchive` reads them (the 8K Remade pack is 1.8 GB, 120 of its images 8192 across); the limit counts what is kept. `native/texture_packs.cpp` indexes the packs at boot, a later pack's image over an earlier's. Every 8 presents `game::TexturePacksFrame` asks GetTextureInfo (0xC5900 with no default, a lookup only: the packs at 0x4830A8 behind the filter 0x483384, then 0x47FA00) for each hash and publishes where its data is ([TextureInfo] + 0x10 the D3D texture) with its size, so an address the track streamer frees and gives another texture is not taken. `native/vulkan.cpp`'s `BindReplacement` binds the pack's image for a texture at that address (not palettized, cube, volume or linear), read and made ready by a thread of its own (`RepLoader`, 96 MB ready at most), 24 MB uploaded a frame at most, the guest's texture till then; a GPU with no BC gets it decoded and at most 512 across. The pack's `_NORMAL`/`_SPEC` maps name textures the Xbox's game has not and are never asked for. TEXTURE RESOLUTION (`texture_resolution`, 512, 1024, 2048 or MAX, 0 as installed) loads each image from its first mip at most that size; a change drops every pack image bound, read again at the new size at its next draw (a ready one made at another cap is made again). Both rows are the GRAPHICS page's last two and are left off it while no pack is installed (`texpacks::Hashes()` empty: read at boot, as the packs are). TEXTURE PACKS (`texture_packs`, the QUALITY page, on by default) off publishes none found, and the next draw of each binds the game's own again; on, the images are read again.

## Conventions

- Native code is C++20 and is compiled with `-fsigned-char -fno-strict-aliasing`, matching x86 semantics.
- Only arm64-v8a is built, minSdk 29 (`native/compat/crt.h` supplies `memfd_create`, which bionic has from API 30). Libraries are linked with 16 KB page alignment.
- Comment style is terse, lowercase, and explains *why*, as in the existing files.
