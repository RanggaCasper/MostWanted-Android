# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An unofficial Android (arm64) port of the original Xbox game *Need for Speed: Most Wanted* Black Edition (title 4541007B), built from the Android host of [Black-Android](https://github.com/RanggaCasper/Black-Android) as [ShaolinMonks-Android](https://github.com/RanggaCasper/ShaolinMonks-Android) carries it, and made with the [XboxXBE-Recomp](https://github.com/TGP482/XboxXBE-Recomp) SDK. The game's x86 code in `default.xbe` is statically recompiled to C++ on a Windows PC. That C++ is then built for Android together with the SDK's portable runtime and this repo's host code. Drawing goes through Vulkan 1.1, and windowing, input and audio through SDL3. The repo ships no game assets. `assets/`, `iso/` and `generated/` hold the user's own files or files derived from them, and all three are gitignored.

## Build

Everything runs on Windows. Requirements: Visual Studio 2022 C++ tools, plus Android SDK Platform 34, NDK `28.2.13676358` and CMake `3.31.6`. Java 17–21 is needed for Gradle 8.7 (`.vscode/settings.json` points to JDK 17). Python is used only to pull the xbe out of an ISO.

- `build.bat` runs the full pipeline:
  1. Checks the tools.
  2. Gets `assets/default.xbe`. If it is missing, `python -I tools/xdvdfs.py <iso> default.xbe assets/default.xbe` extracts it from `assets/*.iso` or `iso/*.iso`.
  3. Builds the recompiler (`tools/CMakeLists.txt` → `out/build/android-tools/xbe_recomp.exe` and `xbe_symbols.exe`) with clang-cl.
  4. Writes the `[symbols]` table into `config/game.toml` with `xbe_symbols`, only if the file doesn't have one yet.
  5. Runs `xbe_recomp config/game.toml --xdk <sdk>/xdk` → `generated/game/`.
  6. Runs `gradlew.bat assembleRelease`.
- To rebuild only the APK after editing host code (no re-recompile): `gradlew.bat assembleRelease`. Output: `app/build/outputs/apk/release/app-release.apk`, signed with the debug key.
- After editing `config/game.toml` (hooks, symbols, ABI, partitions), the recompile step has to run again. Run `build.bat`, or run the two `out/build/android-tools` commands by hand.
- `gradlew.bat assembleDebug` still builds the native code as Release: unoptimized recompiled code is too slow to run.
- Install: `adb install -r app/build/outputs/apk/release/app-release.apk`. On the device, settings (`mostwanted.toml`, `android.toml`, `layout.toml`), saves (`hdd`) and the shader cache are in `Android/data/com.racas.mostwanted/files`; logs in `/storage/emulated/0/MostWanted/logs` when it can be written (all files access), else in `files/logs` (`LogDir` in `native/main.cpp`).
- The first native build compiles 128 partitions of recompiled code and takes 30–90 minutes.
- `-PxbeGenerated=<dir> -PxbeImage=<file>` makes Gradle build recompiled code from somewhere other than `generated/game`.

There are no tests or linters in this repo.

Performance: an empty file named `perf` in `Android/data/com.racas.mostwanted/files` turns on `XBE_PERF` (`native/main.cpp`). The log then gets a line a second from `D3DDevice_Swap` (`src/d3d/d3d8.cpp`, counters in `src/d3d/gpu_frame.h`): fps, the title thread's own time, the render thread's, GPU time from timestamps, draws and renderings; and every 600 frames the frame's renderings with the GPU time of each. `-Pdebuggable` makes `simpleperf record --app com.racas.mostwanted` work; symbolize with the unstripped `libmain.so` under `app/build/intermediates/cxx`.

## CI/CD

`.github/workflows/build.yml` runs on Windows for each `v*` tag, and by hand (workflow_dispatch, artifact only). It decrypts `ci/default.xbe.enc` (not in the repo yet: make it with the command in the workflow's header) with the `XBE_KEY` secret (AES-256-CBC, PBKDF2, 200000 iterations; the command to make it is in the workflow's header), checks its SHA-1, runs `build.bat` with `GRADLE_ARGS` setting `-PversionCode`/`-PversionName` from the tag, and for a tag publishes a release with `ci/release-notes.md` and the commits since the previous tag. `app/build.gradle` signs with a release key from the `BLACK_KEYSTORE*` environment variables when they are set (the workflow sets them from the `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` and `KEY_PASSWORD` repository secrets), else the debug key. Releases since v1.0.0 are signed with the keystore in `.local/` (gitignored); a different key breaks every installed copy's updates. `UpdateChecker.REPO` names the repository whose latest release the app checks.

## Where the SDK comes from

The SDK is vendored in `sdk/` (upstream commit in `sdk/UPSTREAM_COMMIT`), changed in one place: `ExQueryNonVolatileSetting` takes XC_LANGUAGE from a weak `app::ConsoleLanguage()`, which `src/game/game.cpp` defines. Keep `kernel/objects.cpp` notifying every waiter on every signal: notifying only the waiters of the object that changed hung Most Wanted in loading screens (the title spun at 0x087AB5 walking a stream list another thread never filled). Both `CMakeLists.txt` files look for the SDK in this order: `sdk/` in the repo, then `../XboxXBE-Recomp` beside the repo. If neither exists, they FetchContent the SDK's `main` branch. A sibling checkout lets you read or change the runtime (`<sdk>/runtime/{app,core,kernel,xdk,gpu,audio}`), whose headers (`app/app.h`, `kernel/kernel.h`, `xdk/hle.h`, `core/input.h`, ...) the host code includes. Gradle's `fetchSDL` task shallow-clones SDL `release-3.4.16` into `third_party/SDL`. Its Java sources go into the APK and its C side becomes `libSDL3.so`. glslang, toml++ and imgui are fetched by CMake.

## Architecture

The root `CMakeLists.txt` builds one shared library, `libmain.so`, which SDL's activity loads. It is made from:

- **`generated/game/`**: recompiler output (`x86_recomp.N.cpp` for N < `partitions`, `x86_func_mapping.cpp`, `image_symbols.h`). Compiled with `-O2 -w`. Never edit it by hand. Change `config/game.toml` or the host code and recompile instead.
- **The SDK runtime** (`<sdk>/runtime/*/*.cpp`), without the Windows-only parts and the parts this repo replaces. The regex filter in `CMakeLists.txt` drops `app/`, `core/input.cpp`, `gpu/d3d12`, `gpu/render_thread`, `audio/xaudio2`, `xdk/dsound` and `xdk/d3d8`.
- **`src/`**, the game-specific host, organized as `src/<area>/*.cpp` and globbed by CMake:
  - `src/game/`: game hooks and patches. `game.cpp` has the language glue (`app::ConsoleLanguage`) and `WidenAspect` (the cameras' frame width at 0x427C00 set to the frame's aspect). `fe_mouse.cpp` makes the touch screen FEng's mouse (below; its interface is `src/common/fe_mouse.h`). `options_menu.cpp` puts the settings in the game's own OPTIONS menu (below). No `[[hook]]` yet. The code carried over from Black (weapon cheats, mouse look, walk key, FOV, typed names) and Shaolin Monks (cheats, menu and prompt taps found in what it drew) is gone.
  - `src/d3d/`: the title's Direct3D 8 (XDK 5849) entry points. `Direct3D_CreateDevice` also sets the device fields the library's init would (FVF shader, vertical blank event, display flags) and starts the vertical blank thread, which Black did from a hook. `render_thread.cpp` records D3D calls on the game's render thread and replays them on a dedicated Vulkan thread. Vertex, texture and surface memory is read at draw time, the way the console GPU reads it, so XDK fences, busy checks and locks wait on that replay.
  - `src/sound/`: DirectSound reimplemented (buffers, streams, ADPCM decode, mixer, reverb).
  - `src/common/`: `game_info.cpp` defines `app::kGame`, the struct that describes the game to the runtime (title, settings file, option bindings, load/save/init, pad and rumble filters, UI callback). Also here: the settings' rows (`menu.cpp`: `app::rows`, which the game's options menu shows, and the CHEATS page, which the game's menu does not show; the ImGui panel, on F10 and the touch gear, shows the CHEATS page alone, the gear pausing a race first (Start) and opening the panel once the press is out), `options.h` (`game::Options`, saved to `mostwanted.toml`) and translations.
- **`native/`**, the Android host. `main.cpp` runs SDL's window and event loop, the app lifecycle and foreground/surface handling. `vulkan.cpp` is the Vulkan backend, and `vk_shader.cpp` compiles the SDK's HLSL shader translations to SPIR-V with glslang. The rest: `touch.cpp` (touch controls and layout editor, plus keyboard and mouse), `gyro.cpp` (tilt steering), `input.cpp` (controllers, and the settings panel's CONTROLLER page bindings, saved as `[pad]` in `mostwanted.toml`, laid over SDL's mapping), `audio.cpp`, `ui.cpp` (ImGui), and `game_files.cpp`, which finds the game files or ISO and checks the xbe's SHA1 against `kImageSha1`. `host.h` declares the interfaces these parts share. `native/compat/crt.h` is force-included into all host sources (not the generated ones).
- **`app/`**: Gradle module. `MostWantedActivity.java` (package `com.racas.mostwanted`) extends `SDLActivity`. It asks for all-files access (the storage permission on Android 10) and creates `/storage/emulated/0/MostWanted` and `files/assets`, which are where the game files are looked for, along with a `MostWanted` folder at the top of each SD card. `UpdateChecker.java` asks `REPO` (RanggaCasper/MostWanted-Android) for its latest release; it is off while `REPO` is empty.

### How recompiled code reaches the host

`config/game.toml` is the recompiler's input:
- `[xbe]`: path, entry point, XDK version, output dir, `partitions` (CMake reads this number to list the generated sources), and code sections.
- `[symbols]` / `[data]`: addresses of library functions and globals in the image, 0 where the image has none. Host code refers to them through `SYM(Name)` from `image_symbols.h`.
- `[abi]`: register-argument conventions for link-time-code-generated XDK functions.
- `[[hook]]`: entries `at = <x86 address>`, `call = "<Name>"`. The recompiler emits a call at that address to a host function `void Name(X86Context& ctx, uint8_t* base)`, defined in `src/game/`. To add a hook, add the `[[hook]]` entry, define the function, and recompile.

Host code reads and writes guest memory through the kernel helpers (`HostPtr(va)`, `R32`, ...) and guest registers through `X86Context`.

### Supported game versions

Only the USA Black Edition disc: `default.xbe` SHA-1 `f636a16af04171089f879a4bed646e185c734233` (4,739,072 bytes, XDK 5849). The disc root holds `default.xbe`, `update.xbe`, `dashupdate.xbe` and `NFS/` (the game data: `ZDIR.BIN` and `ZZDATA*.BIN`).

### Notes on this image

- No `[abi]` entries: the D3D library is not link-time code generated.
- `xbe_symbols` finds 165 of 238 functions and all 12 data symbols. The other functions are not linked: the `.XTLID` table lists every library export the title uses, and the missing ones are not in it. Resolved by hand at the top of `[symbols]`, each with the code that proves it: `D3DDevice_Reset`, `SetPalette`, `BeginPush`/`EndPush`, `LoadVertexShaderProgram`, `IsBusy`, the three visibility test calls, and `IDirectSoundBuffer_Pause`/`SetEG` (`.XTLID` B0057 and B0067: the DSOUND exports are numbered in alphabetical order). `D3D_FvfShader` (0x384468) is loaded by `D3DDevice_SetVertexShader` at 0x373927.
- The stream exports `.XTLID` B0080, B0090, B0095 and B0096 are thunks to `CDirectSoundStream_FlushEx`, `SetHeadroom`, `SetMixBins` and `SetMixBinVolumes`, which are replaced; B00A3 is `XAudioCalculatePitch`, arithmetic left recompiled.
- Frame shape: 0x427C00 (853, 480 x 16/9 with the widescreen flag) is the front end's and HUD's screen transform (0x0D4888, 0x0D8330: 576 / width across, 448 / 480 down, times the profile's scale at 0x427BFC), set to 480 x the frame's aspect (`game::WidenAspect`). The 3D views' projection (0x0C7740, thiscall, ecx the view's matrices) takes the camera's 16 bit horizontal angle ([[eView + 0x40] + 0xC4]) for the x scale (+0x40) and that angle times 9/16 (3/4 without the flag) for the y scale (+0x54): wider than 16:9 the picture was stretched. `src/game/game.cpp` multiplies the x scale by (16/9) / aspect (Hor+) for the views drawn over the frame (types 1, 2, 4 to 7) inside the call, just before the view x projection product (0x2B91C4 at 0x0C7A04) the frustum's planes come from.
- Vertex programs: besides `SetVertexShader` the game loads programs into the NV2A's 136 program slots (`LoadVertexShaderProgram`, 4 callers) and runs them with `SelectVertexShaderDirect` (0x372F20, 9 callers), which copies a `D3DVERTEXATTRIBUTEFORMAT` to its static record (0x384350, the format at +0x14) and jumps to `SelectVertexShader`. `src/d3d/d3d8.cpp` keeps the slots and makes one `gpu::VertexShader` per inputs and program it is asked to select.
- The Vulkan backend counts no visibility test pixels; `GetVisibilityTestResult` gives 0, which the sun's glare (0x0D5AB0) reads without checking the result.
- 0x2CDBAA is SSE2 code (the recompiler leaves its `pxor`, `psraw`, ... unimplemented); nothing calls or points at it.
- Frame buffers: the present parameters give the title's own surfaces (`BufferSurfaces` 0x0047E1F4/0x0047E478, `DepthStencilSurface` 0x0047FFE8, a 1280x480 multisample depth). Like the library (0x3789D0), `src/d3d/d3d8.cpp` keeps copies of the buffer headers, sized as the present parameters say, and Swap turns the copies over; the title trades its own headers' memory itself before each Swap (0x0C8DA3) for the textures its visual treatment reads. Turning the title's headers too made every other frame black.
- Graphics switches in the QUALITY page, `src/game/game.cpp`: CAR REFLECTIONS (`car_reflections`: FULL, HALF, QUARTER, OFF): the cars' environment cube is drawn as views 0x12 on (0x0D7AD5, face 0's target at [0x48B4C0], the faces' views 0x70 apart) only while the byte at 0x4279D6 is set, one of a row of render switches at 0x4279CC (all 1) the game reads and never writes; HALF and QUARTER set it every 2nd or 4th frame, but every frame out of a race and in a race's first 120 frames (`game::Racing`): a race's cube is new, and its cars stayed white until the count came round. OFF: `native/vulkan.cpp` binds an opaque dark grey cube (matched by address too, `game::g_env_cube`), and the game still draws it every 512th frame: off from the start, a cube never drawn left the paint white whatever was bound. The faces cost about 3% of the GPU's frame. ROAD REFLECTIONS (`road_reflections`): the dword at 0x427A3C, read only at 0x0D787B, gates the wet road's reflection (views 4 and 5); the road still samples view 4's target, so off binds opaque black for it (`game::g_road_reflection`). SHADOWS (`shadows`): the dword at 0x469910, read only by a car's render (0x255490), gates the shadow under each car (0x24C0F0 with the CARSHADOW texture at CarRenderInfo +0xE0, 0x24BB90 with the one at +0xE4). The trees' and buildings' shadows on the road are the frame's one 2x multiply draw into the frame (blend DST_COLOR/SRC_COLOR); SHADOWS off skips it in `native/vulkan.cpp`. (A pale car once blamed on that skip was CAR REFLECTIONS off.) PARTICLE EFFECTS (`particles`): the byte at 0x4279CF, read only at 0x0D81FC, gates the particle system's draw (0x0CE8B0, the system at 0x482CC0). Not the master switch at 0x434130, which also stops spawning (0x0DA296 to 0x0DBEE4): loading a race with it at 0 corrupted the game's heap, a crash in the allocator 0x054DC0 under 0x1C0D50. The game's switches are written by `game::ApplyGraphicsSwitches` at each present. SCREEN RAINDROPS (`rain_drops`): 0x0CC530, the "Rain Drop" pass (20 drops, 40 renderings a frame), returns at once. FALLING RAIN (`rain`): 0x2527A0 draws a view's precipitation ([view + 0x68], views at 0x48ACF0, 0x70 each; 350 drops at +0x33D8, the RAINDROP texture at +0x3404) and returns at once; its caller 0x25E770 still works out the rain's strength (+0x290) that wets the road. YELLOW TINT (`yellow_tint`, off by default): the "Visual Look Pass" (0x0CDA40, pixel shader 0x17 of the effect table at 0x42A858) is lerp(luma, scene, +0x98), the scene times a curve of its alpha by +0x90, plus the scene times a tint ramp (texture 3, 256x1 at [this + 0x234]), plus the 320x240 copy by +0x170, times 1 + 4 x +0x174. 0x0C1BD0 builds the ramp from the curve at +0x50 and the RGB at +0xA0/+0xA4/+0xA8, the yellow; off, that colour is its luma while the ramp is built and is given back after. The pass is not skipped: it reads the scene (0x47FC2C) and draws to [this + 0x298], likely the frame itself. MOTION BLUR (`motion_blur`): the "Motion Blur" pass 0x0D1440 (cdecl, 4 args, from the "Visual Look Filters" 0x0D21D0 while the byte at 0x42F51D is set) returns whether it drew, and the "Radial Blur Mask Pass" (0x0CE1C0, nitrous and speedbreaker) runs only then; slow, it returns false having drawn nothing (0x0D1661), so off returns false at once.
- Cheats in the ImGui panel (its only page), not the game's options menu (`src/game/game.cpp` `ApplyCheats`, at each present): INFINITE NITROUS and INFINITE SPEEDBREAKER set debug bytes the game reads and never writes, 0x49A61C (the NOS drain at 0x1E6A9A is 0, every car's) and 0x4B9694 (LocalPlayer's speedbreaker drain at 0x20E663). MAX CASH keeps CareerSettings::CurrentCash, `[[0x48EDD4] + 0x10] + 0xB4` (the FEDatabase's first profile), at 9,999,999; it ends up in the save. NO POLICE sets the cop manager's byte at +0x60 (`[0x494E40]`, ICopMgr vtable 0x3CB4D0), which the scripts' NoNewPursuitsOrCops sets (0x0130E0) and VehicleSpawningEnabled (0x01A370) reads: no new cops or pursuits; a pursuit already on goes on. Off gives the byte back. UNLOCK ALL holds UnlockAllThings, the byte at 0x493D00 (SkipFE 0x493C40 + 0xC0, as on the PC), which every unlock test ors in; the game sets it itself in one menu (0x1049FA), so off gives it back too. NFSPluginSDK (berkayylmao) has the PC's class layouts, the same as the Xbox's.
- SKIP MOVIES (`skip_movies`, `src/game/game.cpp`): the movie screens' NotificationMessage (FEAnyMovie 0x116230, InGameAnyMovie 0x131A30, the boot's EA logo/PSA/intro/attract 0x1311B0, whose byte +0x2C allows the skip) stop on A/START (0x406415E3/0xB5AF2461) and post the movie's end (0xC3960EB9); the 10th per-frame tick (0xC98356BA) of each screen is taken for A, once a screen (forgotten in its destructor); the boot's screen only once its byte allows (forcing it hung the attract movie), and a player's press after the skip is taken for a tick, as a second end hung the attract movie on its frame. The engine's own cutscenes (NIS: rival intros, the career's opening) are not movies and still play: NISActivity is the class at vtable 0x3E60C0 (GetName 0x21A7F0), the counter at 0x4C8800 is above 0 while one plays (0x214399/0x215E10), and HUDACTION_SKIPNIS (0x32) maps to category 2, bit 0x80000 in 0x21DD60; what reads that bit is not found yet.
- The ImGui panel draws with the game's body font (`src/game/game_font.cpp`, `ui::ApplyGameFont` in `native/ui.cpp`): once FONT_MW_BODY is loaded (cFEng's font list at 0x48F2F0, the node's name hash at +0x14 = bStringHash("FONT_MW_BODY") 0x545570C6, its TextureInfo at +8, its FNTX resource at +0xC), its glyphs (16 bytes each: Unicode +0, width +2, height +3, texture x/y +4/+6, x offset +9, y offset from the line's top +0xA, advance +0xE) are cut out of its 256x256 linear DXT3 texture and laid into ImGui's atlas as custom glyphs over ProggyClean at the game's line height (+0x24, 23), which stays for what the game's font lacks; the renderer uploads the atlas again (`ImGui_ImplVulkan_CreateFontsTexture`, which waits for the queue). Until then (the first seconds of the boot) the panel is ProggyClean. `FontGlobalScale` brings the taller font to the 13 px the panel was laid out for.
- The retail build's PIX marker stub 0x377A70 (`xor eax, eax; ret`) is called with each pass's name ("World Render", "Car Render", "Rain Drop", "EnvMap %d", ...) and each loose model group's (0x0D62A0): wrapping it to log names maps the renderer. It is shared by other empty functions, so check the name pointer with `mem::IsCommitted` before reading it.
- Sound: EA's software mixer plays through one 6 channel PCM buffer (0x2DF96E, mix bins 0 to 5), so `src/sound/mixer.cpp` mixes up to 6 channels a voice; dropping the centre and back channels silenced cutscene dialogue and the engines.
- On Adreno `native/vulkan.cpp` uses render passes (cached, clears as load ops) instead of dynamic rendering: `vkCmdBeginRendering` allocated on every call, a sixth of the render thread in the rain, where the screen drops ping-pong 20 times a frame between the frame and a 32x32 target. Command pools are reset on a thread of their own (the driver's reset frees and remaps the buffers' GPU memory).
- SHADER PRELOADING (`shader_preload`, PERFORMANCE page, off by default): `native/vulkan.cpp` lists every shader (its key, vkey or pkey ^ kPixelKeySalt, to its HLSL's hash) and pipeline (its PsoKey, values only) the first time it is made, in `shadercache/preload.bin`, whether the option is on or not. On, a detached thread makes them all from the cached SPIR-V (`vkshader::Cached`) and `BuildPipeline`, the render passes made first on the render thread; `EnsurePipeline` and the shaders take them under `pre_lock_`, and a pipeline the render thread makes first is claimed so the thread skips it. A race and the menus are about 50 shaders and 50 pipelines; with the driver's pipeline cache they preload in well under a second.
- `native/vulkan.cpp` keeps a depth buffer larger than the target (the zeta has its own pitch); it used to drop it, and the scene drew with no depth test (the car's interior over its body).
- Split screen (two pads plugged in): each player's world is drawn into the frame with a half viewport, then each half's visual treatment is drawn to a 640x240 surface over the frame's own rows (the top one at the frame's address, the bottom one 240 rows in) and reads that half as a 640x240 texture. Targets are keyed by address, so the top half made the frame again every frame (black under the HUD) and the bottom one was a target of its own. `native/vulkan.cpp` draws and clears such a surface into the presented frame, rows down (`FrameRegion`), and a texture over a presented frame's rows is copied out of it at each bind (`BindFrameRegion`).
- Pixel combiners are read from the combiner registers (`MakePixelKey`, `sdk/runtime/gpu/shaders.cpp`), which the render thread now copies (`src/d3d/render_thread.cpp`): Most Wanted sets them with pixel shader render states after `SetPixelShader`, over a definition that is all but empty.
- The scratch push buffer walker applies the inline `SetVertexShaderConstant` (NV097 0x1EA4/0x0B80) and raw program loads (0x1E9C/0x0B00), and every draw walks it first (`SyncDeferred`).
- Fog with table mode NONE is vertex fog: a program's `oFog` is the factor (`fogp.w == 4`); Most Wanted's final combiner blends by the fog alpha.
- `D3DDevice_IsBusy` reports idle (the title spins on it at 0x0BEB30).
- Kernel exports added to the SDK: 76 `IoQueryVolumeInformation` (fails; the disc position of a file becomes 0, 0x2BE8EE) and 8 `DbgPrint`.
- Settings in the game's menu (`src/game/options_menu.cpp`, host functions replacing recompiled ones with `X86_FUNC`, no `[[hook]]`): UIOptionsMain (0x104C70, the title's OPTIONS and the pause menu's) shows the sections when opened as ANDROID OPTIONS, an icon of the main menu beside its OPTIONS (the main menu's Setup calls 0x128AB0 back to 0x104C0F; OPTIONS is its last icon, vtable 0x3D534C). That icon's React sets the FEDatabase flag 0x10 (+0x12C) as OPTIONS' does (0x0E3F30), so the main menu's fade opens MainMenu_Sub.fng's UIOptionsMain (0x11697E), whose Setup (0x128AB0 called back to 0xED82C) then gets GRAPHICS, CONTROLS (touch, keyboard, controller) and GENERAL (general, credits), categories 0x20 to 0x22, in place of the game's icons: those are deleted as Setup adds them (0x12A120 from 0xED5FC to 0xED81E). Ours are told by their vtable, not their address: a game icon is often new where one of ours was freed, and taken for ours it stayed in the list. A section's options screen leaving for the options (SwitchPackage returning to 0x105479) comes back to the sections, on the one left (0x128AB0's answer, the package's last icon, is replaced). The pause menu gets ANDROID OPTIONS too, beside its OPTIONS (Setup 0x105A00, its 0x128AB0 back to 0x105A5B; OPTIONS vtable 0x3D537C, React 0x0EEC30, which opens Pause_Main.fng's UIOptionsMain on 0x33195CF0, 0x10F12A): ANDROID OPTIONS' React calls OPTIONS' own, and takes its byte +0x45, which the pause menu's icons set (0x0EEEC1) and without which the scroller calls no React on Accept (0x139884). The game's OPTIONS keeps its own icons only. The pause options screen's header title is a language string (type 5): it is set with 0xEAB30 to a hash of ours (0x52430100 + section) that SearchForString answers (`SetOwnString`, src/game/prompts.cpp). FEPrintf cuts a text to its string's room (0xE11B3, the header's 14 letters), so `Print` reserves it first (0x15D680). Its scroller has a slot object an icon (`option_1` on, ten in Options.fng, seven the game's), so the panel's six pages are three sections. Accept's fade opens Options.fng/Pause_Options.fng for them (0x104D40), and UIOptionsScreen::Setup's default case (0x153080 called back to 0x105758) gets toggle widgets (0x5C, ctor 0x13A800, added by 0x139D40) whose Act, Draw and Position are `dispatch::HostThunk`s writing with FEPrintf (0xE11F0, Latin-1 text). A string's place is justified through its font when set (0xEA970), so a row is placed again after its text changes, its title's middle half the font's measured width (0x138060) before the arrow; without the widescreen flag the letters are narrower than the stretched layout (x 640 / (480 x aspect)). The screen has row objects (`OPTION_NAME_n`) for nine rows: a longer section scrolls its rows through nine widgets on Up/Down (0x155D50). Y's defaults are 0xEE570. The icons are made by `tools/option_icons.py` (`src/game/option_icons.inc`, drawn as the game's: gears and a subject, white) and handed out by GetTextureInfo (0xC5900) as copies of OPTIONS_ICON_AUDIO's TextureInfo with an A8R8G8B8 swizzled D3D texture.
- The touch controls (`native/touch.cpp`) are a whole Xbox pad in one layout, a racing game's (gas and brake pedals, Black the camera, the right stick the gear lever), which the editor moves and resets. RESET (`reset_car`, top left of Back, races only) puts the car back on the road: `game::ResetCarFrame` (`src/game/game.cpp`, at the present) does what EResetPlayerCar does (0x1B3640), the first player's IResetable (interface 0x19AFC0, found by 0x169A80 on [player + 4]) ResetVehicle(false) (vtable +8, 0x1FF390), the last place ResetCar kept. Its STEERING setting (`steering` in `layout.toml`) picks the steering: arrows, a wheel dragged round, or the phone tilted (`native/gyro.cpp`, the accelerometer's up in the screen's plane; `tilt_angle` in `android.toml` is the tilt for a full lock).
- Menus by touch (`src/game/fe_mouse.cpp`): FEng kept the PC's mouse. cFEng at [0x48E94C], its first field the FEngine: `bMouseActive` +1, first package +0xE0, interface +0x108 (vtable +0x44 `GetMouseInfo`, an empty `ret 4` shared at 0x19BC0, so the slot is pointed at a `dispatch::HostThunk`). FEPackage: next +4, control mask +0x20, input +0x28, current button +0x8C, mouse states +0xAC/count +0xB0 (0x10 each, bit 0 of +0xC over). The mouse is on only around a touch in a package with regions. FEng's screen is centred, 480 high and 480 x aspect wide: the layout is that wide with the widescreen flag, and without it (under 3:2) the 640 wide layout is stretched, but its hit tests still take 480 x aspect. The console's screens dropped the PC's mouse code: package scripts still answer clicks (MainMenu's arrows, a dialog's OK), a tap on the highlighted button presses A (hit test `FEngTestForIntersection` 0x10CF20, called with `CallGuest`), swipes step the dpad, and an A/B/X/Y diamond stays in menus for screens no tap reaches. Out of a race, a package that takes input with no regions but shows a pad prompt (a tutorial's "Press (A) To Continue") is a menu too, its mouse off, and a tap anywhere on one prompting A is its A. The prompts' textures are named for the PS2's buttons (A CROSS, B TRIANGLE, X SQUARE, Y CIRCLE, the triggers L1/R1, the right stick RIGHT_ANALOG): a menu prompting the triggers (Showcase.fng's zoom, the world map's) gets LT/RT pills above X and Y, labelled ZOOM OUT/ZOOM IN where the game's label is no action (the map's "ZOOM 1.5X"); one prompting RIGHT_ANALOG (the showcase turning the car, the map's cursor) takes a drag as the right stick, and gives FEng's pointer a touch only once it ends as a tap (pressed at once, the drag's release clicked the map's GPS). The game's keyboard (Keyboard.fng, a profile's name) is a 15 column grid of FEng buttons (flag bit 28; Space's, Lowercase's, Backspace's and Done's cells too) with no mouse regions: FEng's mouse is turned on for it, and a tap makes the key under it the package's current button (FEPackage::SetCurrentButton 0x15CB30, thiscall, the object and 1 to send the highlight messages) and presses A. FEngTestForIntersection tests an object's own place only, leaving its groups out, so a key is tested by its cached render object (+0x58: size +0x30/+0x44, middle +0x60/+0x64 in the front end's 640x480), which is drawn into the middle 576x450 of FEng's screen (0.9 across, 0.9375 down, measured off the frame). Its X, Y, L and R prompts' pills are not shown (their labels are not theirs).
- HUD layout (`src/game/hud_layout.cpp`, `src/common/hud_layout.h`): the layout editor moves the speedometer, the minimap, the race information (top right: RaceInformationGroup, LeaderBoardGroup, 0x9AFCE2B8, 0x2269D232) and EA_TRAX.fng's song banner (group 0xA1341735, in the front end too) (boxes under the controls, `[hud]` in `layout.toml`, FEng units). HUD_SingleRace.fng's groups are found by name hash (FEHashUpper 0x157E40; FEObject: hash +0x10, type +0x18, data +0x2C with x/y at +0x1C/+0x20; FEGroup children count +0x60, first +0x64; FEPackage name +0xC, objects +0x4C) and moved after FEngine::Update (0x165B20, wrapped): Hud_Minimap writes TRACK_MAP's place every frame, so moved at the present its roads stayed behind. Speedometer: GaugeCluster, SpeedometerGroup, TURBO_GROUP, the speedbreaker's and nitrous' gauges (in group 0x5D0101F1 with the race information). Minimap: TRACK_MAP, the icons' group 0x00A1A862, TRACKMAPTARGETRING, the roads 0xB0F63386 and the rim with the heat level 0xC46A80A9. Drag races' HUD_Drag.fng is not moved.
- Prompts for the touch screen (`src/game/prompts.cpp`): every string lookup goes through SearchForString (0x124B50, hash in edx, the table at [0x48EDC4], Latin-1 text); the "Press START" strings and the tutorials' "Press" are answered with "Tap anywhere" and the like, per language. The hashes are the same in every language's table (chunk 0x39000 in ZZDATA). Indonesian, which no disc has, answers the rest of the table too, from `src/game/strings_id.inc` (generated: the English table read off the disc, 4466 strings, translated; names, cars and places stay English).

## Conventions

- Native code is C++20 and is compiled with `-fsigned-char -fno-strict-aliasing`, matching x86 semantics.
- Only arm64-v8a is built, minSdk 29 (`native/compat/crt.h` supplies `memfd_create`, which bionic has from API 30). Libraries are linked with 16 KB page alignment.
- Comment style is terse, lowercase, and explains *why*, as in the existing files.
